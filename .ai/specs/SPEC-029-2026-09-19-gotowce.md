# Gotowce — skrót przypisania szablonu FiziYo

## Cel biznesowy

Terapeuta po utworzeniu pacjenta przypisuje gotowy szablon na najczęstszy przypadek w maksymalnie 3 krokach, bez budowania zestawu od zera. Źródło: protokół rady 2026-09-18, rozmówca K01: „daj zestaw pod kolano skoczka → gotowiec”.

Rozszerza SPEC-007 (template vs plan) o UX skrótu; always-fork (`PATIENT_PLAN`) zostaje.

## Architektura

1. Wizard ładuje szablony org (`exerciseSets`) **oraz** katalog FiziYo (`fiziyoTemplateExerciseSets` — istniejąca query backendu, `ExerciseSetQuery.GetFiziyoTemplateExerciseSets`). Merge i dedupe po `id`.
2. Krok `select-set` pokazuje sekcję „Gotowce FiziYo” (`templateSource = FIZIYO_VERIFIED`) na górze: nazwa, liczba ćwiczeń, chip przypadku (match nazwy/opisu/ćwiczeń, bez nowego pola GraphQL).
3. Klik kafelka seeduje parametry i częstotliwość ze szablonu i pomija `customize-set` oraz `schedule`, skacząc do `summary` (albo `select-patients`, gdy pacjent nie jest preselected). Kroki pominięte zostają we wskaźniku.
4. Na podsumowaniu „Dostosuj podstawowe parametry” wraca do `customize-set` (copy: nigdy „dawkowanie”).
5. CTA „Przypisz gotowiec” na wierszu pacjenta, po utworzeniu pacjenta i na pustym stanie karty otwiera wizard z `intent=gotowiec`.
6. Always-fork bez zmian: `createExerciseSet(kind: PATIENT_PLAN)` + mappingi + `assign`.

Mobile (SPEC-011) nie kopiuje tego skrótu w tym etapie.

## Interfejsy

### GraphQL Queries/Mutations

Klient portalu dodaje odczyt istniejącej query (additive, bez zmiany schematu):

```graphql
query GetFiziyoTemplateExerciseSets {
  fiziyoTemplateExerciseSets {
    ...ExerciseSetWithExercisesFragment
  }
}
```

Mutacje assignment bez zmian.
